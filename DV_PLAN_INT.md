# `rdma_subsystem` — Integration DV Plan

Status: **PLAN — pending review.** Subsystem-level DV plan for the
4-IP `rdma_subsystem` cosim. Per-IP DV plans live under each submodule's
`tb/DV_PLAN.md`.

## 1. Scope

This DV plan covers integration cosim only. Each of the 4 sibling IPs
(`rdma_dma_engine`, `rdma_sq_fetcher`, `rdma_cq_pusher`, `rdma_run_manager`)
has its own per-IP UVM regression that signs off the IP. This plan
exercises the **assembled subsystem** end-to-end:
- OPQ source (AXI4-Stream, 36 b TDATA) drives the `rdma_dma_engine` input.
- All 4 IPs wired per `RTL_PLAN_INT.md` (xbar, CSR passthrough, reset chain).
- A behavioral software model of **run_tool** drives the BAR1 CSR
  (AXI4-Lite), posts SQEs into a host-DRAM model region, polls the CQ ring,
  and sequences run-state transitions.
- Goal: prove **OPQ frames are conserved end-to-end into the host
  rx_buffer** under realistic run-phase transitions (idle → preparing →
  running → stopping → stopped, plus reset).

Per `ARCHITECTURE_PLAN.md §1`: no midas event_builder in the FW path.
The host rx_buffer is just a contiguous run of mu3e frame bytes, written
verbatim by `rdma_dma_engine`. Any midas downstream is software, not
in scope of this DV plan.

The FEB is **abstracted away** — the OPQ source stub generates synthetic
frames that emulate post-OPQ behavior at the byte level (sop K28.5 BC,
eop K28.4 9C, hit-pattern body words). No FEB-side stimulus, no SciFi
path, no rbCAM. This keeps cosim runtimes manageable and isolates
subsystem-level invariants from FEB-specific bugs.

## 3. Software-behavioral run_tool model

The TB agent `runtool_model_agent` mirrors the host's `mu3e_capture` /
`run_tool` orchestrator behavior in SystemVerilog. It is the **canonical
host-FW interaction model** used by the cosim. It runs on the cosim
event-driven scheduler, not as a separate process.

### 3.1 State machine

```
                   reset_n high
                       v
                +--------+
                | IDLE   |<------------------+
                +--------+                   |
                  | runtool.start_run()      |
                  v                          |
                +-----------+                |
                | PREPARING |                |
                +-----------+                |
                  | drain CQ from prior run  |
                  | program SQ_BASE_*, CQ_BASE_*, SQ_DEPTH, CQ_DEPTH
                  | program FEB EMU CSRs (out of scope, mocked)
                  | post N pre-staged SQEs into host SQ ring
                  | write SQ_TAIL_DBL doorbell
                  | write CTRL.enable=1
                  v                          |
                +---------+                  |
                | RUNNING |                  |
                +---------+                  |
                  | poll CQ_TAIL; per CQE harvest the rx_buffer named by SQE
                  | top-up SQ ring with new SQEs as they retire
                  | runtool.stop_run() OR error -> STOPPING
                  v                          |
                +----------+                 |
                | STOPPING |                 |
                +----------+                 |
                  | write CTRL.halt=1 OR enable=0
                  | drain remaining CQEs (timeout-bounded)
                  | snapshot final counters
                  v                          |
                +---------+                  |
                | STOPPED |------------------+
                +---------+
```

### 3.2 Behaviors per state

**PREPARING**
- Allocates one host-DRAM region per pre-staged SQE (each region 4 KB
  multiple per `seg0_span` rules in `ARCHITECTURE_PLAN.md §5`).
- Writes the SQ ring with N SQEs (default N = SQ_DEPTH/2). Each SQE
  names its rx_buffer with `seg0_addr / seg0_span` (and optionally
  `seg1_*` for cross-boundary cases).
- Writes `CTRL.enable=1` last. From this point, the FW owns the SQ.

**RUNNING**
- Polls `CQ_TAIL` every `poll_period_ns` (default 1 µs).
- On every observed CQ_TAIL advance: reads the new CQE(s) from the CQ
  ring, captures `bytes_written_total`, `seg0/1_bytes_written`,
  `status`, `event_count`, `first/last_event_ts`, `opq_drop_snapshot`,
  `retire_seq`.
- On CQE: validates the named rx_buffer against the OPQ-source
  scoreboard (every byte the OPQ source generated MUST be present in
  some rx_buffer slot, in order, with no holes other than EOE/FULL
  partial-line padding).
- On valid CQE: writes `CQ_HEAD_DBL = new_head` to credit FW.
- Maintains a free-pool of rx_buffers and posts new SQEs as the pool
  drains. SQ_TAIL_DBL doorbell is coalesced (post N SQEs, then one
  doorbell write).

**STOPPING**
- Writes `CTRL.enable=0`. FW must not consume new SQEs.
- Continues to poll CQ_TAIL for `drain_timeout_us` (default 1 ms) to
  collect in-flight retires.
- Asserts that final `CNT_SQE_CONSUMED == CNT_CQE_POSTED` (every fetched
  SQE produced a CQE).
- Asserts that `CNT_BYTES_WRITTEN == sum(seg{0,1}_bytes_written across
  all CQE)` (no double-counting in the engine counters).

### 3.3 Configuration knobs (test parameters)

- `n_pre_staged_sqe` (1..SQ_DEPTH/2)
- `sq_depth`, `cq_depth` (power of 2; default 16)
- `seg0_size`, `seg1_size` (4 KB multiples; 0 = unused)
- `seg1_used` (bool; whether SQEs name 2 segments)
- `opq_rate_q88` (Q8.8 hits/cycle)
- `opq_n_lanes` (1..4 OPQ lanes feeding through)
- `poll_period_ns` (CQ poll cadence)
- `doorbell_coalesce_n` (post N SQEs per SQ_TAIL_DBL write)
- `drain_timeout_us`
- `stop_trigger_after_n_cqe` (early stop test)
- `inject_reset_at_cqe_n` (mid-run reset test)

## 4. Validation invariants (subsystem-level scoreboard)

The subsystem scoreboard cross-validates 4 different views of every byte:

1. **OPQ source ledger** — every 32-b word the source agent injected,
   tagged with a sequence id.
2. **DMA-write trace** — every AXI4 W-channel beat captured by the
   `host_axi_completer_agent`, with target address and bytes-written.
3. **Host rx_buffer reconstructed** — for each SQE, the buffer
   contents, with bytes-written count from the CQE.
4. **CQE ledger** — every CQE read by `runtool_model_agent`, with all 8
   fields per `ARCHITECTURE_PLAN.md §5`.

Invariants:

- **Byte conservation**: `Σ source 32-b words × 4 == Σ rx_buffer
  non-pad bytes` (modulo OPQ idle drops which are documented and
  tagged in source ledger).
- **Order preservation**: rx_buffer reconstruction must match OPQ
  source order across all SQEs. No re-ordering inside the FW path.
- **CQE conservation**: `count(CQE) == count(retired SQE) ==
  CNT_SQE_CONSUMED == CNT_CQE_POSTED`.
- **Per-CQE bytes match**: `CQE.bytes_written_total == sum of rx_buffer
  non-pad bytes for the SQE-named region`.
- **EOE matching**: when `CQE.status[EOE]=1`, the OPQ source ledger
  must show an OPQ eop k-character at the corresponding sequence id.
  When `CQE.status[FULL]=1`, the SQE total span was exhausted and the
  next SQE must continue at the next OPQ source byte.
- **Run-state legality**: every CSR transaction observed at BAR1 maps
  to a legal current-state action per the run_tool state machine.
- **DEBUG=1 vs DEBUG=2 cross-check** (per dv-workflow OoO-datapath
  section): when both envs run, every per-hit sidecar id observed at
  DEBUG=2 must map to a valid byte in the DEBUG=1 functional payload.

## 5. Bucket plan (128 cases each)

Per dv-workflow `dv_bucket_format_check.py`:

### 5.1 DV_BASIC_INT.md (B001-B128)

Standard nominal-traffic cases:
- B001-B016: bring-up (reset, CSR identity, CSR R/W, doorbell pulse)
- B017-B032: single-SQE drain, EOE-terminated, single-segment
- B033-B048: single-SQE drain, FULL-terminated, single-segment
- B049-B064: 2-segment SQE drain, seg-boundary crossing
- B065-B080: N back-to-back SQEs (N=2,4,8,SQ_DEPTH-1)
- B081-B096: full state-machine traversal (idle→preparing→running→stopping→stopped) at varying N
- B097-B112: doorbell coalescing (post 1, post 2, post 4, post 8 per kick)
- B113-B128: per-CQE field ground-truth (all 8 fields verified per CQE)

### 5.2 DV_EDGE_INT.md (E001-E128)

Boundary cases:
- E001-E016: SQ ring wraparound, depth=2 / 4 / 16 / 65536
- E017-E032: CQ ring wraparound + credit-window minima
- E033-E048: 4 KB span boundaries (seg0_span = exact 4 KB, 8 KB, 1 MB)
- E049-E064: minimum / maximum buf_addr alignments
- E065-E080: idle OPQ for long periods (engine should not retire CQEs)
- E081-E096: simultaneous SQ post + CQ drain + OPQ stream
- E097-E112: doorbell race (host writes while FW is mid-fetch)
- E113-E128: power-of-2 depth boundaries; mask boundaries

### 5.3 DV_PROF_INT.md (P001-P128)

Stress / performance:
- P001-P032: sustained throughput (OPQ at line rate for 100 µs / 1 ms)
- P033-P064: SQ at full depth, CQ drained at varying paces
- P065-P096: AXI4 host stalls (waitrequest at 25%/50%/75%)
- P097-P128: long-soak conservation (10 ms simulated, sample-based)

### 5.4 DV_ERROR_INT.md (X001-X128)

Fault / illegal / recovery:
- X001-X016: BRESP=SLVERR on host writes (DMA, CQ)
- X017-X032: RRESP=SLVERR on host reads (SQ fetch)
- X033-X048: ALIGN_ERR — SQE with misaligned addr / non-4-KB span
- X049-X064: malformed SQE (invalid opcode, zero buf_len_bytes)
- X065-X080: reset during PREPARING / RUNNING / STOPPING
- X081-X096: CTRL.halt mid-run, then re-enable
- X097-X112: CQ-full backpressure (host doesn't credit)
- X113-X128: forced HALT (FIFO almost-full at packer)

## 7. Phasing

| Phase | Scope | Validation surface |
|------:|-------|--------------------|
| Phase 1 — semi-permanent (this commit) | Full 4-bucket × 128-case suite. AXI4 host completer = behavioral SV agent backed by sparse memory model. OPQ source = synthetic SV agent. | `tb_int/DV_REPORT.md` all-green. |
| Phase 2 — board-level | Same TB topology, but the AXI4 master output is bridged to the real Altera A10 PCIe HIP. Hardware-in-the-loop. | Hardware capture + offline analysis. |

## 8. Hardware integration assumptions (informational)

This DV plan assumes the supercore output AXI4 master is consumed by a
behavioral host model in cosim. The real hardware path (Phase 2) puts an
AXI4↔AVMM bridge between the supercore and the existing PCIe HIP. The
bridge is **not** part of this subsystem's DV — it has its own existing
sign-off from prior work. The `tb_int` cosim does not exercise the
bridge.

## 9. Risks / open questions

- **Timing realism of behavioral host**: the cosim host-AXI completer
  has configurable latency (default 200 ns RTT for reads, 100 ns for
  writes). Phase 2 hardware will see real PCIe TLP latency; if cosim
  passes but hardware capture shows OPQ overflows that cosim missed,
  we'll need to widen the latency profile in `tb_int`.
- **MSI-X**: tied to 0 in Phase 1; no cosim coverage.
- **Multi-QP**: Phase 1 = single QP. Phase 2 may add N QPs; not in scope.
